## Bugs

- #BUG-0006 Detection time grows quadratically with file size: `findVaultBlocks`, `parseMarkers`, `scanText` and `inlineTargets` take about 1 ms for 100 lines, 27 ms for 1k and 280 ms for 4k (`describeDocument` twice that), and `hasVaulted`/`plainView` about 415 ms for 500 `!vault` blocks. Measured by [AVE-0018](features/AVE-0018-benchmarks.md) (`test/bench/baseline/detection-*`). Root cause found: it is the `yaml` library (2.9.1), not our walk. The CST parse is linear (16 to 64 ms for 2k to 8k lines) but composing the Document is quadratic, and the cause is its duplicate-key check on large flat maps; our `lineStart` walk costs under 1 ms. `parseAllDocuments(text, { uniqueKeys: false })` takes 16k lines from 3696 ms to 177 ms. Proposed: pass `uniqueKeys: false` in `inlineTargets` (`src/inline/yaml-values.ts`). Open: today a duplicate key makes `ok` false, which disables edits; keep that behavior with our own Set-based linear check over the top-level keys, or drop it? Affects every caller of detection (#AVE-0012, #AVE-0006, #AVE-0013, #AVE-0010, #AVE-0015). [P1/D2]

- #BUG-0007 One event, many full parses. Each cursor move (150 ms debounce) runs `inlineTargets` four times: `describeDocument` calls `findVaultBlocks` and `parseMarkers`, then `src/ui/status.ts` calls both again; the folding, CodeLens and code-action providers each parse again. One save parses five to six times (`guardReasons` twice, `planSave` plus `parseMarkers` plus `wholeFile`, `snapshot`), and `safeText` computes the reasons before checking `allow === "plain"`. `toggleMarkerEdit` parses twice. Proposed: memoize `inlineTargets` on the last text or document version, and let `describeDocument` return the blocks and markers it already has. Affects #AVE-0006, #AVE-0007, #AVE-0011, #AVE-0012, #AVE-0013. [P1/D2]
- #BUG-0008 Synchronous work blocks the extension host. `pbkdf2Sync` in `src/vault/format.ts` costs about 15 ms per encrypt or decrypt (see [AVE-0018](features/AVE-0018-benchmarks.md)), and `NativeBackend` is async in name only, so `Promise.all` in `encryptAllInFile`, hover decrypts and workspace rekey all serialize on the UI thread. Also blocking: `spawnSync("node")` in `src/diff/index.ts`, and the sync file reads in `src/secrets/resolver.ts` and `src/secrets/sources.ts`. Proposed: async `crypto.pbkdf2` and async reads. Affects #AVE-0001, #AVE-0002, #AVE-0003, #AVE-0015. [P2/D2]
- #BUG-0009 Secret sources are re-read, and password scripts re-run, on every decrypt. `SecretResolver.candidates()` calls `sources()`, which runs `cfgSection()` (four `existsSync` plus a `readFileSync` of ansible.cfg) and `readSource` for each source, reading password files and spawning executables; `labels()` rebuilds `sources()` too. `tryKnownSecrets` calls `candidates` once per label, and `decryptForBuffer` once per block, so opening a file with 50 blocks can run a password script 50 times; every hover does the same. Proposed: build the sources once per operation and cache source reads per resolver, invalidated on configuration change. Affects #AVE-0003, #AVE-0004, #AVE-0007, #AVE-0013. [P1/D2]
- #BUG-0010 Rekey Workspace scan reads the whole workspace serially. `scanWorkspace` (`src/rekey/index.ts`) runs `findFiles("**/*")`, then one `stat` and one full read per file up to 1 MB in sequence, and `textDocuments.find` per URI (O(files x open documents)). Proposed: a Map of open documents, bounded parallel reads, and a cheap prefix check before reading the whole file. Affects #AVE-0010. [P2/D2]

## Tech debt

- #BUG-0011 Reverse-sorted string splicing is copy-pasted five times: `rekeyText`, `plainView`, `decryptForBuffer`, `planSave` and `saveEdit`. Each splice copies the whole text, O(n x k). Proposed: one `applyTextEdits(text, TextEdit[])` next to `TextEdit` in `src/inline/edits.ts`. Affects #AVE-0006, #AVE-0008, #AVE-0009, #AVE-0013, #AVE-0015. [P3/D1]
- #BUG-0012 The vault header is parsed in four places: `HEADER` and `fileVaultId` in `src/detect.ts`, `header()` in `src/inline/yaml-values.ts`, `headerLabel` in `src/vault/backend.ts` and `parseEnvelope` in `src/vault/format.ts`. `DEFAULT_LABEL` is defined twice (`backend.ts`, `src/secrets/ansible-cfg.ts`). `decryptWithSecrets` and `decryptQuiet` call the full `parseEnvelope` (which hex-decodes the body, 33 ms at 1 MB) only to read the vault ID, and the backend then parses it again. Proposed: one header parser in `src/vault/`. Affects #AVE-0001, #AVE-0004, #AVE-0012. [P3/D2]
- #BUG-0013 Small helpers are duplicated. `MAX_SCAN` is defined in four files (`src/rekey/index.ts`, `src/peek/hover.ts`, `src/ui/status.ts`, `src/guard/index.ts`); EOL detection from text appears four times (`src/commands/index.ts`, `src/edit/session.ts`, `src/rekey/rekey.ts`, `src/diff/plain.ts`); three sha256 helpers (`hashText`, `textHash`, `plainHash`); `lineStart` and `lineEnd` are split across `yaml-values.ts` and `src/transparent/markers.ts`; `e instanceof Error ? e.message : String(e)` appears six times; two glob-match helpers (`peekExcluded`, the guard's `globMatch`); three "find the open document by URI" lookups and three "read a file as UTF-8" helpers. Proposed: a small `src/util.ts` and shared `vscode-util` additions. [P3/D1]
- #BUG-0014 Shared pieces live in the wrong layer. `RefusedError` is defined in `src/inline/edits.ts` but imported by seven modules, and `seal()` lives in `src/commands/session.ts` but is used by inline, edit, rekey and transparent code, so lower layers import from `commands/`. Proposed: `src/errors.ts` for the error classes and `src/vault/` for `seal`. [P3/D1]
- #BUG-0015 Dead and stale code. `textHash` in `src/peek/peek.ts` is unused; `VaultBackend.rekey` is implemented twice but only tests call it; `registerCommands` keeps a "not implemented yet" fallback and a comment saying "the rest stay stubs" although all 18 commands have handlers, and its `AVE-0014:` comment is missing the `#`. Open: keep the fallback as a guard that package.json and the handlers agree? [P3/D1]
- #BUG-0016 Duplication in the command layer. The collect-failures-and-join pattern appears three times (`fileCommand`, `decryptAllInFile`, `rekeyWorkspaceCommand`); `decryptAllInFile` re-implements `findVaultBlocks` and calls `getText()` twice; the `target.vaultId === undefined ? { secret } : { vaultId, secret }` ternary is written twice in `src/rekey/index.ts` although both branches equal `{ vaultId, secret }`; `pickVaultId` and `pickRekeyId` build and sort their items the same way. Affects #AVE-0004, #AVE-0005, #AVE-0006, #AVE-0009, #AVE-0010. [P3/D1]
- #BUG-0017 The save guard is an implicit state machine. `registerSaveGuard` (`src/guard/index.ts`) is a 190-line closure with five mutable per-document fields (`pending`, `allow`, `restore`, `held`, `override`) and order-dependent branches in `safeText` and the save handler; the `held` and `pending` branches overlap. Proposed: extract the transitions into a pure, unit-tested module like `src/guard/snapshot.ts`. Affects #AVE-0009, #AVE-0011, #AVE-0013. [P3/D3]
